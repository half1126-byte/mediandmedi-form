# 기능 갭 분석: medischedule.co.kr vs 우리 앱

분석 기준일: 2026-04-08  
참조 URL: `medischedule.co.kr` (폼), `medischedule.co.kr/schedule_admin.html` (관리자)

---

## 1. 폼 페이지 갭 (medischedule.co.kr vs /schedule-change)

### ❌ 우리 앱에 없는 기능

| 항목 | medischedule | 우리 앱 | 비고 |
|------|-------------|---------|------|
| **진료월 자유 선택** | 년도 dropdown + 월 dropdown으로 자유롭게 선택 | 화살표로 이전/다음 탐색만 가능, 다음달로 고정 시작 | 과거 월 재제출 또는 먼 미래 월 입력 불가 |

### ✅ 우리 앱이 더 나은 점 (참고)

| 항목 | medischedule | 우리 앱 |
|------|-------------|---------|
| 출력 사이즈 옵션 | 팝업, A4, 세로형 DID, 가로형 DID (4개) | 팝업(가로/세로), A4(가로/세로), 세로형 DID, 가로형 DID (6개) |
| 거래처명 입력 | 텍스트 직접 입력만 | 자동완성 드롭다운 (기존 거래처 목록) |
| 태그 UX | 태그 선택 → 날짜 클릭 (동일) | 동일 + 지우개 모드 + 토스트 힌트 |
| PC 레이아웃 | 단일 컬럼 | 좌(달력) + 우(폼) 2컬럼 반응형 |
| 이벤트 placeholder | `ex) 3/27~4/27 ㅇㅇ 이벤트` | `예: 5/1~5/15 화이트닝 이벤트 30% 할인` (더 구체적) |

## 2. 관리자 페이지 갭 (schedule_admin.html vs /admin/schedule)

### ❌ 우리 앱에 없는 기능

| 항목 | medischedule | 우리 앱 | 비고 |
|------|-------------|---------|------|
| **월별 탭 건수 배지** | 각 월 탭에 해당 월 제출 건수 숫자 표시 (예: 5월 `49`, 6월 `1`) | 없음 (선택된 월 총 건수만 헤더에 표시) | 어떤 달에 제출이 몰렸는지 한눈에 파악 불가 |
| **관리자 메모** | 상세 패널 하단에 관리자 전용 메모 입력 섹션 | 없음 | 내부 인수인계용 메모 기록 불가 |
| **일정 내용 직접 수정** | 목록 카드에 "수정" 버튼, 상세 패널에 "✏️ 수정" 버튼 → 제출된 일정 데이터 직접 편집 가능 | 없음 (상태/담당자 변경만 가능, 삭제 후 재제출 필요) | 오탈자·누락 수정 시 원장님께 재제출 요청해야 함 |
| **새로고침 버튼** | 우측 상단에 명시적 새로고침 버튼 | 없음 (월 탭 전환 시 자동 로드, 수동 강제 갱신 불가) | 실시간으로 새 제출 확인 시 페이지 새로고침 필요 |

### ✅ 우리 앱이 더 나은 점 (참고)

| 항목 | medischedule | 우리 앱 |
|------|-------------|---------|
| 처리 상태 관리 | 없음 | 접수 / 제작중 / 검토요청 / 완료 인라인 변경 |
| 담당자 배정 | 없음 | 이하은 / 김민지 / 박서연 인라인 배정 |
| 연도 전환 | 없음 (2026년 고정) | 2025 / 2026 / 2027 탭 전환 |
| 달력 상세 | 단순 태그 표시 | 공휴일명 병기, 태그 우선순위 정렬, 중첩 태그 +N 표시 |
| 목록 상태 배지 | 없음 | 처리 상태 컬러 배지 |

## 3. 내부 직원 피드백 (2026-04-08)

| # | 피드백 | 영향 페이지 | 현황 | 비고 |
|---|--------|------------|------|------|
| F-1 | **PC에서 화면이 너무 좁다. 기존 폼(medischedule)은 화면이 꽉 차 있는데 우리 앱은 여백이 너무 많다. PC·모바일 모두 더 꽉 찬 화면이면 좋겠다.** | `/new-clinic`, `/contract-change`, `/schedule-change` | `new-clinic`·`contract-change`는 `max-w-2xl`(672px), `schedule-change`는 `max-w-5xl`(1024px). 4K 모니터에서 양쪽 여백이 지나치게 큼 | medischedule은 약 700px 고정폭이지만 다크 배경이 전체를 채워 "꽉 찬 느낌"을 줌. 우리는 밝은 배경에 좁은 콘텐츠 영역 |

### F-1 원인 분석

```
현재 max-w 설정:
  /new-clinic       → max-w-2xl  (672px)  ← 좁음
  /contract-change  → max-w-2xl  (672px)  ← 좁음
  /schedule-change  → max-w-5xl (1024px)  ← 적당하나 배경 여백이 허전함
  /admin/schedule   → full-width (좌패널 380px 고정 + 우측 flex-1)  ← 양호

medischedule 비교:
  폼 영역 자체는 ~700px이나 다크 배경(#1a1a2e 계열)이 전체 화면을 덮어
  시각적으로 꽉 찬 느낌을 줌. 우리 앱은 흰 배경에 콘텐츠가 중앙에 떠 있어 좁아 보임.
```

### F-1 개선 방향 (구현 시)

| 방안 | 설명 | 난이도 |
|------|------|--------|
| **A) max-w 확장** | `new-clinic`·`contract-change`를 `max-w-3xl`(768px) 또는 `max-w-4xl`(896px)로 확장 | 쉬움 (클래스 교체) |
| **B) 배경 확장** | 콘텐츠 영역 배경색을 section 단위로 분리해 전체 폭에 구분선 표시 | 중간 |
| **C) new-clinic PC 2컬럼화** | schedule-change처럼 PC에서 좌(기본정보) + 우(진료/시설 등) 2컬럼으로 분리 | 어려움 |

> **권장:** A안 먼저 적용(1시간) → 실제 사용 피드백 수집 후 C안 판단

### F-2: 태그 선택 후 여러 날짜 연속 적용

| 항목 | 내용 |
|------|------|
| 피드백 | 날짜 표시 유형(예: 휴진) 선택 후 달력 날짜를 클릭하면 태그가 적용되고, 태그를 다시 해제하지 않고도 여러 날짜를 연속으로 선택할 수 있어야 한다 |
| 영향 페이지 | `/schedule-change` |
| 현황 | ✅ **이미 구현됨** — `activeMode` 상태가 날짜 클릭 후 초기화되지 않아 연속 선택 기술적으로 가능 |
| 실제 문제 | ❌ **UX 피드백 부족** — 태그 버튼의 선택 강조(scale-105, shadow-md)가 약해 사용자가 "모드가 여전히 활성 상태"임을 인식하지 못함. medischedule은 선택 태그를 풀컬러 강조(붉은 배경 + 흰 텍스트, 테두리 없음)로 명확하게 표시함 |
| 개선 방향 | 선택된 태그 버튼에 ring-4, 더 강한 색상 대비, 하단 안내 문구("휴진 모드 활성 중 — 날짜를 클릭하세요") 상시 표시 |

## 5. 구현 우선순위 제안 (통합)

### P1 — 실무 영향 큼
1. **폼 화면 너비 확장** (직원 피드백 F-1) — `new-clinic`·`contract-change` `max-w-2xl` → `max-w-4xl`로 확장. 구현 30분.
2. **일정 내용 직접 수정** — 원장님 재제출 없이 관리자가 직접 수정 가능해야 함. 상세 패널에서 달력 태그 및 이벤트·요청사항 편집 후 저장.
3. **관리자 메모** — 담당자 간 인수인계, 특이사항 기록. Notion 속성 1개 추가(`관리자메모`, Rich Text) + 상세 패널 textarea.

### P2 — UX 편의
4. **월별 탭 건수 배지** — 전월 API 호출 or 현재 데이터 집계. 모든 월 데이터를 한 번에 fetching하면 성능 이슈 → 월별 count만 별도 경량 API로 처리.
5. **새로고침 버튼** — 버튼 1개 추가, `fetchRecords()` 호출. 구현 5분.

### P3 — 폼 개선
6. **진료월 dropdown 선택** — 현재 화살표 탐색 방식도 직관적이나, 먼 달 이동 시 불편. 드롭다운 추가 또는 "년/월 직접 입력" 옵션 고려.

## 6. 총평

우리 앱은 medischedule 대비 **처리 상태·담당자 관리, 반응형 레이아웃, 거래처 자동완성, 지우개 모드** 등 핵심 업무 기능에서 앞서 있음.

빠진 기능 중 실무 영향이 가장 큰 것은 **"관리자가 직접 일정 수정"** 기능으로, 현재는 오류 수정 시 원장님께 재제출을 요청해야 하는 불편이 있음.
