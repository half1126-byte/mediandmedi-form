01 / INTAKE

거래처 접수 웹앱

외부 거래처가 입력한 정보는 Vercel 웹앱을 거쳐 Notion 거래처DB에 저장됩니다. 업무용으로 쓰지 않는 속성은 웹앱 저장 대상에서 제외하는 방향으로 정리했습니다.

내부 사용자가 체크해야 다음 단계가 시작됩니다.

02 / OPENING

신규개원 12개 업무

`신규 업무 생성`이 체크되고 생성 상태가 미완료인 거래처만 처리합니다. 기존 표준 업무는 유지하고 빠진 업무만 보완합니다.

1

대상 확인

체크 여부와 업무 생성 상태를 검사합니다.

2

중복 검사

동일 거래처·표준 업무명 기준으로 0·1·2건 이상을 판정합니다.

3

누락 업무 생성

첫 인사부터 최종 개원 점검까지 표준 12종을 구성합니다.

4

체크리스트 연결

업무마다 필터된 업무 체크리스트DB 보기를 연결합니다.

5

거래처 완료 처리

모든 검증 성공 후에만 Relation과 생성완료 상태를 저장합니다.

03 / MEETING → DONE

미팅 기록부터
업무분배·완료까지

녹음과 수기 모두 같은 검토 관문을 통과합니다. 사람이 실행할 내용을 확정하고 승인한 뒤에만 업무가 생성되며, 체크리스트가 100%가 되어야 종료됩니다.

🎙 녹음으로 시작

  1. Notion 음성 메모 또는 녹음 파일 저장
  2. 받아쓰기·요약으로 논의 내용을 구조화
  3. 결정사항과 사내 실행 항목 후보를 추출
  4. 담당자가 원문과 비교해 액션 아이템을 확정

✍️ 수기로 시작

  1. 미팅 본문은 형식 없이 자유롭게 작성 가능
  2. 담당자가 결정·요청·검토·아이디어를 구분
  3. 실행이 확정된 항목만 액션 아이템으로 이동
  4. 업무 하나당 한 줄로 정리하고 모호한 표현 제거
공통 승인점
사람이 내용을 검토한 뒤 미팅 상태=완료 + 업무 생성 요청=체크
STEP 1

미팅 기록 수집

녹음 또는 수기 본문과 거래처·참석자·미팅 담당자를 한 미팅 페이지에 모읍니다.

STEP 2

내용 전처리

인사말·반복·아이디어를 걷어내고 실제 실행이 필요한 문장만 업무 후보로 정리합니다.

STEP 3

사람 검토·승인

업무명·대상 거래처·실행 범위를 확인합니다. 자동 요약만으로는 생성되지 않습니다.

STEP 4

안전 조건 검사

완료 상태, 생성 요청, 거래처 1곳, 유효 액션을 확인하고 중복 업무를 검사합니다.

STEP 5

팀 분류

내용을 마케팅·바이럴·디자인·웹 업무로 분류합니다. 미지원·모호 항목은 생성하지 않습니다.

STEP 6

담당자 결정

마케팅은 거래처DB 담당마케터를 우선하고, 다른 팀은 미팅 담당자를 기준으로 검증합니다.

STEP 7

(신)업무DB 생성

업무명·관련거래처·담당팀·담당자·상태를 저장하고 원본 미팅 Relation을 연결합니다.

STEP 8

직원 실행

업무 페이지의 필터된 체크리스트에서 실행하고 결과 링크·캡처·접수번호 등 증빙을 남깁니다.

STEP 9

진행률 자동 집계

업무 체크리스트DB의 완료 체크 수가 Rollup으로 집계되어 진행률이 올라갑니다.

STEP 10

업무 완료·종료

체크리스트가 1개 이상이고 모두 완료되면 업무상태를 완료로 바꾸고 종료일을 기록합니다.

오류 시 동작: 거래처 없음·복수 연결, 담당자 불명확, 동일 업무 중복, 지원하지 않는 팀이면 업무를 만들지 않습니다. 원인을 업무 생성 오류에 기록하고 운영자가 수정한 뒤 다시 승인합니다.
04 / GATES

무작정 생성되지 않는 조건

아래 네 조건을 모두 만족해야만 미팅 액션 아이템이 실제 업무가 됩니다.

1

생성 요청 체크

체크 해제 이벤트나 일반 편집은 아무 작업 없이 종료합니다.

2

미팅 상태 완료

진행 중이거나 시작 전인 기록은 업무화하지 않습니다.

3

신 거래처 1곳

거래처가 없거나 여러 곳이면 오류로 중단합니다.

4

유효 액션 존재

빈 문장·제목·검토 중 표현·중복을 제거합니다.

분류가 모호하거나 담당자가 불명확하면 추측하지 않습니다. 업무를 만들지 않고 `업무 생성 오류`에 원인을 남깁니다.
05 / ROUTING

담당팀·담당자 배정

조아라 고정 배정이 아니라 거래처와 미팅의 실제 담당 관계를 우선합니다.

업무 유형담당팀담당자 기준안전 조건
광고·검색·플레이스·마케팅 실행마케팅팀거래처DB의 담당마케터사람DB에서 재직 + 마케팅팀 + 정확히 1명
바이럴·카페·커뮤니티바이럴팀미팅DB 담당자정확히 1명 지정
이미지·인쇄물·디자인 제작디자인팀미팅DB 담당자정확히 1명 지정
홈페이지·팝업·GEO/AEO·웹 수정웹팀미팅DB 담당자정확히 1명 지정
영상·유튜브·숏폼·촬영미지원생성하지 않음현재 (신)업무DB에 영상팀 선택지가 없어 오류 처리
06 / SYNC

체크리스트와 완료율

업무 본문에 체크리스트를 중복 작성하지 않고 업무 체크리스트DB를 단일 기준으로 사용합니다.

업무 페이지

필터된 Linked View

해당 업무 UUID만 보이도록 필터하고 순서 오름차순으로 표시합니다.

직원 실행

완료 체크

필요한 항목은 결과 링크·캡처·접수번호 등 증빙을 먼저 남깁니다.

Rollup

완료율 상승

완료 체크 개수에 따라 (신)업무DB 진행률이 집계됩니다.

100%

업무 완료

체크리스트가 1개 이상이고 전부 완료일 때만 업무상태를 완료로 바꿉니다.

종료

종료일 기록

완료 전환 실행일을 종료일로 저장하고 이미 완료된 업무는 재수정하지 않습니다.

07 / STATES

미팅 업무 생성 상태

운영자가 현재 단계를 빠르게 확인할 수 있는 네 가지 상태입니다.

대기

아직 생성 요청 전이거나 재검토 중

생성중

중복 검사 및 업무 생성 진행 중

생성완료

업무 Relation 저장까지 성공

오류

원인 기록 후 요청 체크 자동 해제

08 / ACTUAL FLOW

웹앱 입력부터
Notion 업무 실행까지

아래 화면을 위에서 아래로 읽으면 실제 운영 순서가 됩니다. 거래처의 웹앱 입력이 거래처DB에 저장되고, 미팅 검토를 거쳐 (신)업무DB의 실행 업무로 이어집니다.

🔒 공개 안전본웹앱은 빈 입력 화면이며, Notion은 실제 거래처명·구성원명·업무 행을 캡처에서 제외했습니다.
09 / QA

현재 검증 결과와 남은 일

Vercel 배포와 Notion 웹훅 연결은 완료되었습니다. 운영 전 실제 샘플 미팅 1건으로 종단 간 검수하는 것이 마지막 단계입니다.

  • 미팅 전용 API 배포 및 Vercel 배포 성공
  • Notion 자동화 `미팅 액션 아이템 → (신)업무DB` 활성화
  • 인증 없는 외부 요청 401 차단 확인
  • 녹음·수기 액션 아이템 전처리 테스트 추가
  • 체크 해제 재호출 시 무동작 처리
  • 중복 검사 및 부분 생성 실패 시 신규 업무 롤백

운영 보완 권장

  • 미팅DB 기본 화면에 생성 요청·상태·오류 속성 표시
  • 중복된 미팅지침 문서 통합 및 오탈자 수정
  • 수기 입력용 액션 아이템 예시 추가
  • 영상팀 속성과 담당자 규칙 확정
  • 테스트 거래처·미팅 1건으로 E2E 검증
